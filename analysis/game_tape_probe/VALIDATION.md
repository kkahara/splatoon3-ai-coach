# "GAME!" tape detector: freeze and held-out validation (pre-registration)

Frozen 2026-10-19, before any held-out frame was scanned. Approved by the
user as "freeze + genuinely held-out validation"; **no `src/` integration,
historical re-analysis or `AGENTS.md` change** until a separate approval
after this validation. Nothing below is adjusted after held-out results are
seen.

## Frozen detector

- Tools: `tools/diagnostics/game_tape_probe.py` (features),
  `tools/diagnostics/game_tape_validate.py` (rule, validation).
- Frames: 2 per second, decoded at 480x270.
- Mask: `band_mask.png`, sha256
  `efa538023384bad7f2c1a9c4ceacbfeef8744537d74523533b89cb40567ca619`,
  built from four development references (2026-10-11 playerview
  `22-57-30:318.0`, `22-20-42:326.0`, `22-31-53:221.5`, `18-25-16:199.5`).
- Features: `fill` (band pixels on the bands' dominant saturated hue) and
  `contrast` (pixels just outside the bands off that hue). The text-hole
  feature is not used (it depends on the "GAME!" glyph layout).
- Frame rule: `fill >= 0.73` and `contrast >= 0.35`.
- Detection: at least 2 consecutive positive frames; the onset is the run's
  first frame.

Development data (12 2026-10-11/12 playerview recordings, all English): the
thresholds were set midway between tape frames (fill >= 0.810, contrast
>= 0.475) and gameplay frames with high fill (contrast <= 0.216). Under the
frozen rule: one run per video at the true end, 7-16 frames long, and no
positive frame anywhere else (6,743 gameplay frames). Not held out.

## Held-out set

`heldout/heldout.json`, generated by `select` before scanning: every video
in `~/Movies` with duration 100-480 s, excluding the 12 development
recordings and names containing review / preview / timeline / nocontest /
results. 187 videos, 15.1 h: language by file-name prefix only, en 74, ja 49
(`ja` / `jp`), unknown 64 (no prefix or `jn`). Includes two recordings made
after development (`en_SW2--2026-10-19 ...`). Mode, tape color and ending
type are not known in advance; they are recorded during labeling.

## Truth labeling

After `run` and `sheets`, and before `report`:

1. **Onset pages** (`pages/onsets_*.jpg`): every detected run, frames from
   onset - 2.0 s to + 0.5 s. Label whether it is the tape and the true onset
   (first sampled frame showing any part of the tape).
2. **Whole-video grids** (`grids/`, one thumbnail every 2 s) for every
   video without a run, plus a seeded sample of 20 videos with a run
   (seed 20261020): label every tape ending visible (count, approximate
   onset, refined from frames if needed).
3. Videos with a run and no grid inspection are assumed to contain only
   that ending. This is a stated residual risk (a 100-480 s video rarely
   holds two endings); the 20-video grid sample estimates it.
4. Per ending, record (in `notes`) the ending type (time / knockout /
   overtime, from the clock in the frames before the tape), tape color and
   mode when visible.

`truth.csv` is committed before `report` runs.

## Pass criteria

A run is **on time** if it starts no later than 1.0 s after the true onset,
**late** if it starts within 10 s after it, and **false** if it matches no
true onset.

The frozen detector passes if all hold:

1. 0 false runs across all 187 videos.
2. Recall (endings with a matched run / all labeled endings) >= 0.95
   overall and within every language group with at least 10 endings.
3. On-time rate (on time / matched) >= 0.95.

Every miss, late run and false run is examined and reported whether or not
the criteria pass. A failure means the detector is revised and validated
again on recordings that played no role in either round; these held-out
videos then become development data.
