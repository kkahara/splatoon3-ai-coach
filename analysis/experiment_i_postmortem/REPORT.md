## Method

Every unresolved evidence path in the 88 call records (33: 32 in arm M, 1 in
arm A) is one row, with the citation exactly as emitted. Classification rule,
written before the table was generated:

- **A** namespace / path mismatch, unambiguous supplied evidence: exactly one
  supplied view leaf is reachable from the citation, by dropping leading
  namespace segments (`prefix`) or through the block that carries the cited
  `source_path` label (`label_block`), and its value equals the cited value
  under the production comparison (`_same`).
- **B** ambiguous: more than one such leaf matches, or matching and
  non-matching candidates coexist.
- **C** unsupported: no such leaf and no leaf anywhere with the cited final
  key and an equal value.
- **D** other.

Each row also records whether the literal path exists in the view (never, by
construction) and whether the path names a serialized CoachInput field
(pydantic schema walk including computed fields).

### Finding 2: the 28 `primary_context.map_awareness.*` citations come from two conflicting conventions in the prompt

- The production system prompt (both arms) says "When evidence_used cites a
  fact, prefer the exact CoachInput path and value", with examples
  `primary_context.death_episode.death_to_respawn.value = 6.0`,
  `primary_context.relations...`, `primary_context.combat...`; it also says
  "prefer `source_path` values from the view", and the view's labels are
  `primary_context.map`, `primary_context.death_episode`,
  `primary_context.special.nearest_before_anchor`, ... (7 of the 13 labels
  in the 22-57-30 @308.0 view begin with `primary_context.`).
- `map_awareness` is serialized at the **top level** of the view
  (`map_awareness` sits beside `map`, `special`, `timeline`), has no
  `source_path` label and is not part of CoachInput.
- The arm-M section and the experiment claim use the correct top-level form
  (`map_awareness.seconds_back_in_play`; claim `evidence_paths`
  `map_awareness.seconds_back_in_play` / `.map_checks_since_back_in_play`).
- Result (`citation_forms.json`): the 28 eligible arm-M outputs split exactly
  14 top-level (28 citations, all resolved) and 14 `primary_context.` (28,
  all unresolved). The form differs between the two repeats of the same input
  at 8 of 14 deaths, so it is sampling between the two taught conventions, not
  a property of the death. In arm A, 54 `primary_context.*` citations resolved
  through labels; the convention is normal production behavior and resolves
  where a label exists.

Answers to the trace questions:

1. Yes. The citation rule's examples and most view labels teach
   `primary_context.*` as the evidence namespace.
2. Yes, `map_awareness` is top level (no `primary_context` object exists in
   the view; `primary_context` appears only inside label strings).
3. Yes. View blocks projected from `primary_context` (map, death episode,
   special readings, zone control, score) carry `primary_context.*` labels, so
   placing a new per-death block there is structurally understandable.
4. Yes. The experiment claim and the section used `map_awareness.*`.
5. See Finding 4.
6. The other five hits are the same class of problem with different
   mechanics (Finding 3).

### Finding 3: the other four arm-M hits and the arm-A hit are view-projection / label-vocabulary gaps

- `game_clock_samples[label=death].observation.display` (2 M, 1 A): the exact
  CoachInput path. The view's clock block carries the label
  `game_clock_samples[label=death]` but flattens `observation.*` into itself
  (`clock.display`), so walking `observation.display` under the label fails
  (`unknown_key`). The view even carries the sibling label
  `game_clock_samples[label=death].observation.seconds_remaining` (an
  importance-factor path), which models the `observation.` segment.
- `primary_context.special.state_at_anchor` (1 M): the exact serialized
  CoachInput path (computed field on the special evidence). The view projects
  it to top-level `special.state_at_anchor`; the `special` block has no label
  (only its child readings do), so it cannot resolve.
- `primary_context.timeline.time_since_previous_death.value` (1 M): a hybrid.
  CoachInput has `primary_context.timeline.time_since_previous_death` (a
  float, no `.value`); the view block is labelled `durations` and holds
  `timeline.time_since_previous_death.value`. The model combined the
  CoachInput namespace with the view's shape.
- Pre-existing, independent of Experiment I: two of the five citation
  examples in the production system prompt never resolve against any of the
  22 sealed views (`primary_context.relations.leads_to_death_episode_id`,
  `primary_context.combat.trade_candidate`: `unknown_block` in 22 / 22); the
  related example fails in 7 / 22 (`unknown_key`). The prompt teaches
  citations the validator rejects.

### Finding 4: yes, the stop-point-2 smoke test missed the form the model produced

The only smoke case with `evidence_used` (`intended`) cited
`map_awareness.seconds_back_in_play = {seconds}`, the top-level form copied
from the section. Missing cases: the same citation under the prompt's own
namespace convention (`primary_context.map_awareness.seconds_back_in_play`,
`primary_context.map_awareness.map_checks_since_back_in_play`), and any
citation of `map_checks_since_back_in_play`. More generally, the smoke inputs
were authored, not sampled, and no test checked that the prompt's citation
examples resolve.

### Finding 5: the ratings follow a handful of templates keyed to whether a supported recommendation is present

- 88 rows use 5 distinct rating patterns (usefulness / redundancy / anchor /
  missing context / supported / map_use) and 7 distinct notes; repeats r1 and
  r2 got the identical pattern at 44 / 44 (death, arm) pairs.
- All 28 eligible arm-M rows: `4 / 2 / 4 / 3 / yes / correct`, one identical
  note ("Observed no-map-check interval directly supports the map-check
  recommendation; broader tactical context is not shown.").
- Usefulness tracks recommendation presence: arm-A eligible outputs had no
  recommendation in 28 / 28 (rated 2 x24, 3 x4); arm-M eligible outputs had
  one in 28 / 28 (all 4). Elsewhere, no recommendation -> 2, a non-map
  recommendation -> 3, in both arms. Non-eligible and null-block rows have
  identical rating distributions in A and M.
- The notes show the heuristic: "without a recommendation or tactical context
  they provide limited actionable coaching" (32 rows) vs "directly supports
  the map-check recommendation" (28 rows).

Limitation on the value result: the ratings measure, in effect, "a supported
recommendation is present" for this unit type, applied by template; they are
not 88 independent judgments. The 1.857 gain is the 2 -> 4 template step, not
an estimate with uncertainty. Within-arm repeat variation is zero, so the
comparison with the 0.1364 floor is degenerate (any template difference
exceeds it). Arm A could not give map advice (production rule), so the value
comparison also confounds "map coaching" with "any recommendation". The value
gate's pass is weak evidence of usefulness.

### Finding 6: smallest principled next step

Make the citation contract single-sourced and tested before changing any
behavior: a contract test that every citation the prompt teaches (citation
rule examples, section paths, claim `evidence_paths`) resolves against fixture
views. It changes nothing, would fail today on two production examples, and
would have caught Finding 4. The first behavioral fix to investigate after it
is choosing one convention for view-projected fields (proposal 2 below). For
`map_awareness` specifically, the principled question is where the derived
fact lives (CoachInput / coaching layer vs. view-only); any label or path for
it follows from that decision, not from whitelisting the cited string.

Not proposed: whitelisting `primary_context.map_awareness.*` (or any
prefix-stripping rule) in the validator. It would turn Experiment I's
counterfactual into a pass without deciding where the fact lives, and a
general prefix strip would also accept citations that move fields between
objects, which the prompt forbids ("Never move a field from related to
primary_context").

## Recommended next decision

Approve proposal 1 (contract test, no behavior change) as the next step, and
decide separately between proposals 2 / 3 / 4 for the convention, together
with proposal 6 if the map-awareness unit is to be pursued. Rating
methodology (proposal 7) should be fixed before any successor experiment
relies on a value gate.
